# Contributing

Thank you for helping build this project.

## Before opening code

1. Read the README, roadmap and security policy.
2. Open an issue describing the problem, intended users and acceptance criteria.
3. Keep pull requests focused and include tests or reproducible examples.
4. Do not submit real victim data, credentials, malware, private records or unlawfully obtained material.

## Quality bar

- Explain the threat model or user need.
- Prefer deterministic, offline tests.
- Document assumptions and limitations.
- Never present generated or inferred output as verified fact.
- Use clear commit messages and update documentation with behavior changes.

By contributing, you agree that your contribution may be distributed under the repository license.
